For developers

This technical document provides guidelines and structural information regarding the source code, decompilation, and development environment for Catch The Coins, developed by DanywkaGames.

Engine Compatibility Requirement:

This project relies on features and API specifications implemented in modern GDScript versions. Opening or launching this project requires Godot Engine version 4.7 or higher. Attempting to run or build the project on earlier Godot 4.x versions may result in parsing errors or broken signal bindings.

1. Decompilation & Source Code Analysis

Decompiling, analyzing, or reverse-engineering the binary or packaged assets (.pck) for research or educational purposes is permitted. Developers examining the codebase must observe the following terms:

  • Educational Rights: Developers may analyze algorithms, UI management systems, and GDScript implementations for personal learning.
  • Asset Ownership & Commercial Restrictions: The game logic, graphics, branding, and original audio files remain the intellectual property of DanywkaGames. Unedited redistribution, commercial exploitation, or re-uploading modified builds under a different name is prohibited.

2. Technical Architecture & System Dependencies

Developers modifying or analyzing the codebase should take note of critical structural requirements:

  • Autoload Singletons: Central management systems like ProgressManager must remain registered as active singletons. Essential game data including coin counts, unlocks, and achievement states depend on this node.
  • UI Hierarchy & Deferred Sizing: Hidden UI components (such as WhatCoinPanel and WhatCoinBG) utilize deferred initialization. Modifying their initial visibility without handling frame waits (e.g., await get_tree().process_frame) will cause incorrect bounding box and pivot point calculations during dynamic scale animations.
  • Dynamic Text Overrides: Achievement notification banners dynamically override font sizes (e.g., scaling strings down to 33px for specific keys) based on layout constraints. Overriding these controls may lead to UI overflow on low-resolution displays.
  • Input & Platform Adaptation: Control schemes automatically toggle between physical input handlers and touch UI controls based on configuration settings stored in user://settings.cfg.

Files & Folders That Must NOT Be Deleted Under Any Circumstances

Deleting any of the following key files, folders, or root nodes will cause an irreversible failure of the project structure, parsing errors, or complete inability to compile and run the game:

  • Root Nodes: The primary Control node located at the top of the scene tree.
  • Scene Files: All .tscn files (scene structures and UI layouts).
  • System Godot Files: .godot, .pck, and .uid files, as well as the .godot directory.
  • Configuration Files: .import, .gitattributes, and .gitignore files.
  • Critical Scripts: ProgressManager.gd and achievement_message.gd.
  • System Resources: The fonts folder and the CustomizationSkins folder.

If you want to completely trash and break the game, feel free to delete all of these :)

3. Data Persistence & Save Management

Local data storage is formatted and saved to the user:// directory. Modifications to save keys or data structures should maintain backward compatibility with established dictionary keys to prevent data corruption upon initialization.
